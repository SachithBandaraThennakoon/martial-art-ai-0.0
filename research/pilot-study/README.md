# Single-participant expert feasibility case study

This directory contains the executable protocol for the final live evidence stage.
The scope was adapted on 2026-07-31 to one researcher-expert participant, jab only,
using a laptop camera. It is not population-level effectiveness evidence.

## Authoritative documents

1. `PILOT_AND_FRAMEWORK_EVALUATION_PROTOCOL.md` — design, outcomes, annotation,
   bias controls, and analysis rules.
2. `FIELD_RUNBOOK.md` — checklist to follow on the recording laptop.
3. CSV templates — session/trial registry, phase annotation, feedback rating,
   usability, failure log, and artifact manifest.
4. `../tools/analyze_pilot.py` — validates files and creates descriptive summaries.

## Non-negotiable gates

- Obtain institutionally appropriate consent before recording. The supplied
  checklist is operational documentation, not a substitute for ethics approval.
- Use participant ID P001 in structured data and protect identifiable media.
- Retain original consented video in restricted storage and record only its hash
  and controlled location in the research package.
- Annotate source recordings without seeing system condition or output.
- Replay the same recording through both conditions. Do not compare different
  performances as if they were paired.
- Freeze configuration before opening the held-out pilot results.
- The current repository has deterministic coaching, not an operational LLM.
  Therefore this pilot compares `rule_only` with `hybrid_template` only.
- A verified condition switch/replay harness is a pre-pilot software gate. If it
  is unavailable, mark the run blocked; do not simulate or manually relabel a
  normal run as rule-only.

## Suggested private/public layout

Keep identifiable material outside version control:

```text
private-pilot/                 # restricted, not committed
  identity-key/
  consent/
  original-video/
research/outputs/pilot/<run>/ # anonymized evidence and summaries
```

No thesis or report is generated by this package.
